# Aerial Guardian — Multi-Object Tracking Pipeline

Real-time aerial drone person tracking built from scratch.  
Custom **YOLOv8n-P2** detector fine-tuned on VisDrone → **ByteTrack** association → **OpenCV ECC** camera motion compensation.

![Demo](demos/uav0000086_00000_v_tracked.mp4)

---

## What This Project Does

Given a UAV drone video or image sequence, this pipeline:

1. Detects every visible **pedestrian** using a custom 4-scale YOLOv8 model (adds a P2 head for tiny targets)
2. Compensates for camera shake using **ECC (Enhanced Correlation Coefficient)** affine estimation
3. Associates detections across frames using **ByteTrack** — a 3-stage IoU matcher that keeps low-confidence detections alive to bridge occlusions
4. Renders annotated output video with bounding boxes, persistent track IDs, and fading trajectory tails

---

## Architecture

```
Frame (1280×720)
     │
     ▼
FramePrefetcher (daemon thread — reads disk ahead of GPU)
     │
     ▼
YOLOv8n-P2  ──  4-scale detection head (P2/P3/P4/P5)
     │            └── P2 head detects objects as small as ~8px
     ▼
parse_detections()  ──  filter conf < 0.05, return [cx,cy,w,h,conf]
     │
     ├──► ECCCompensator  ──  320×180 grayscale warp estimation
     │         └── compensates Kalman predictions for camera motion
     │
     ▼
ByteTracker.update()
     │   Stage 1: high-conf dets ↔ active tracks  (IoU)
     │   Stage 2: low-conf dets  ↔ remaining tracks (IoU)
     │   Stage 3: unmatched dets → new tentative tracks
     │
     ▼
TrackVisualizer.draw()  ──  boxes, IDs, fading trail tails, FPS HUD
     │
     ▼
AsyncWriter (daemon thread — JPEG compression off the critical path)
     │
     ▼
outputs/videos/<sequence>_tracked.mp4
```

## Environment Setup

### Requirements

- **Python**: 3.10 or 3.11
- **GPU**: NVIDIA GPU with CUDA 11.8 (RTX 3050 6GB or better recommended)
- **OS**: Windows 10/11 or Linux

### Install

```bash
# 1. Clone the repo
git clone https://github.com/Halok600/JOB_PROJECT_III_DRONE.git
cd JOB_PROJECT_III_DRONE

# 2. Create virtual environment
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux/Mac
source .venv/bin/activate

# 3. Install PyTorch with CUDA 11.8 (required for GPU training & inference)
pip install torch==2.1.2+cu118 torchvision==0.16.2+cu118 --index-url https://download.pytorch.org/whl/cu118

# 4. Install remaining dependencies
pip install ultralytics==8.0.236 opencv-python==4.13.0.92 tqdm pillow numpy scipy
```

> **Note on PyTorch version:**  
> The training script and tracker are tested with `torch==2.1.2+cu118`.  
> PyTorch 2.6+ changed `weights_only=True` as default in `torch.load`, which breaks  
> loading `.pt` files saved with older Ultralytics versions. Stick to `2.1.2+cu118`.

### Verify GPU is available

```python
python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0))"
```

## Running the Pipeline

### Step 1 — Preprocess (VisDrone → YOLO format)

```bash
python scripts/01_preprocess.py
```

Optional flags:
```
--raw-dir     data/raw          Source directory (default: data/raw)
--out-dir     data/processed    Output directory (default: data/processed)
--val-split   0.2               Fraction for validation (default: 0.2)
--min-wh      4                 Min bbox size in pixels to keep (default: 4)
```

This generates YOLO `.txt` label files and `configs/dataset.yaml`.

---

### Step 2 — Train

```bash
python scripts/02_train.py
```

Optional flags:
```
--epochs    100     Training epochs (default: 100)
--imgsz     1280    Input resolution — DO NOT change for RTX 3050 6GB
--batch     4       Batch size — MAX 4 at imgsz=1280 with FP16 on 6GB VRAM
--amp       True    FP16 mixed precision (halves VRAM usage)
--workers   2       DataLoader threads (keep low to avoid CPU RAM spike)
--resume            Resume from last checkpoint
```

> **VRAM warning:** `batch=4` at `imgsz=1280` peaks at ~4.8 GB VRAM with FP16.  
> Lower to `--batch 2` if you hit CUDA OOM.

Training takes approximately **8–11 hours** on an RTX 3050 6GB.  
Best weights are saved to `models/weights/best.pt` after training.

---

### Step 3 — Track

```bash
# Image sequence
python scripts/03_track.py \
    --weights models/weights/best.pt \
    --source data/raw/sequences/uav0000086_00000_v

# Video file
python scripts/03_track.py \
    --weights models/weights/best.pt \
    --source path/to/video.mp4

# Disable camera motion compensation (faster but less stable IDs)
python scripts/03_track.py \
    --weights models/weights/best.pt \
    --source data/raw/sequences/uav0000086_00000_v \
    --no-cmc
```

Optional flags:
```
--imgsz         1280    Inference resolution
--track-thresh  0.25    Min confidence to activate a track
--low-thresh    0.10    Low-confidence detections for re-association
--match-thresh  0.80    IoU cost threshold (1 - IoU)
--max-lost      60      Frames to keep a lost track alive (~2s at 30fps)
--trail-len     40      Trajectory tail length (frames)
```

Output video is saved to `outputs/videos/<sequence_name>_tracked.mp4`.

## Key Design Decisions

| Decision | Reason |
|---|---|
| **P2 head added to YOLOv8n** | Standard YOLOv8 P3 head misses objects < 16px. P2 at stride-4 detects ~8px targets. |
| **Single-class (person only)** | VisDrone class 2 ("people" crowds) is excluded — bbox quality too loose for tracking. |
| **imgsz=1280 single pass** | Higher resolution than SAHI tiling but single forward pass — simpler and ~same accuracy. |
| **ECC on 320×180** | Full-res ECC is too slow. 320×180 gives ~40x speedup with near-identical warp quality. |
| **Threaded I/O** | cv2.imread and VideoWriter block ~8–15ms each. Daemon threads overlap these with GPU work. |
| **ByteTrack over SORT** | ByteTrack's low-confidence stage recovers detections during partial occlusion, giving fewer ID switches. |
